# Android WebCam

把安卓手机的**后置摄像头**变成局域网里的安全网络摄像头：同一 Wi‑Fi（或手机热点）下的电脑、平板、另一台手机，用浏览器打开一个地址就能实时观看。不需要在观看端安装任何软件，不经过任何云端。

- 只用后置摄像头，**画面永不镜像**（人物举右手，观看端看到的就是右手，和拍照一致）
- 默认 1280×720 H.264（硬件编码，延迟低、流量小），浏览器不支持时自动切换 MJPEG 兼容模式
- 竖放/横放手机自动旋转画面（也可固定方向），熄屏继续推流
- 支持中文 / English 界面（手机端和网页端都跟随系统语言）

## 签名证书指纹（用于核对 APK 真伪）

所有正式版 APK 都用同一把密钥签名。请只安装签名证书 SHA‑256 指纹为下面这个值的 APK：

```
90:50:AE:5D:8D:5A:43:D9:E6:64:1B:34:A9:6A:0D:8C:2E:CA:44:7B:9F:1C:8D:C5:72:FE:79:0C:A7:E4:44:EB
```

GitHub Actions 在发版时会强制校验这个指纹，不一致就拒绝发布。电脑上可以用 `apksigner verify --print-certs AndroidWebCam-vX.Y.Z.apk` 自行核对（输出里的 `SHA-256 digest` 去掉冒号、转小写后应一致）。每个 Release 还附带 `SHA256SUMS.txt`。

## 下载、安装与升级

1. 打开本仓库的 [Releases](../../releases) 页面，下载最新的 `AndroidWebCam-vX.Y.Z.apk`。
2. 在手机上安装（需要允许“安装未知应用”）。
3. 以后有更新时，下载新版本直接安装即可**覆盖升级**：包名和签名永远不变，版本号（versionCode）每次只增不减，设置会保留。

最低系统要求 Android 10；开发和测试以 **OnePlus Nord N10 5G（BE2026，骁龙 690，6 GB + 128 GB，Android 11 / OxygenOS 11）** 为准。

## 使用方法

1. 手机和观看设备连接**同一个 Wi‑Fi**（也可以让观看设备连接手机热点，或用 USB 网络共享）。
2. 打开 Android WebCam，点 **开始推流**，按提示允许相机权限。
3. 在观看设备的浏览器（Chrome / Edge / Safari / Firefox）打开手机上显示的地址，例如 `https://192.168.1.23:8443`。
4. 第一次打开会提示“连接不是私密连接 / 证书不受信任”。这是因为证书是手机自己生成的（局域网 IP 无法申请公网证书）。**先在浏览器的证书详情里核对 SHA‑256 指纹与手机上显示的“证书指纹”一致**，再选择“继续访问”。指纹一致就说明你连的确实是自己的手机，传输全程加密。
5. 输入手机上显示的 **8 位访问码**；手机/平板也可以直接**扫描二维码**（一次性链接，5 分钟内有效，用过即失效）。

小贴士：

- 推流期间可以直接按电源键熄屏，推流不会中断；通知栏会一直显示“正在共享摄像头画面”和观看人数，点“停止”即可结束。
- OxygenOS 会限制后台应用：请在 App 里点“熄屏后继续推流 → 允许”，忽略电池优化。
- 手机上可以开关闪光灯、调整缩放；“断开所有观看者并更换访问码”会立刻踢掉所有人。
- 一加的辅助摄像头（超广角/微距/黑白）通常只对系统相机开放；如果系统允许第三方应用使用，设置里会自动出现可选的后置摄像头。

## 安全与隐私设计

| 方面 | 做法 |
| --- | --- |
| 传输加密 | 仅 TLS 1.3（AEAD 加密套件、前向保密），拒绝 TLS 1.2 及以下；没有任何明文 HTTP 端口 |
| 服务器私钥 | ECDSA P‑256，生成在 Android Keystore（手机安全硬件 TEE）里，**不可导出**；启用前先在内存里完整握手自检 |
| 证书 | 自签名，满足 Apple/Chrome 的证书规则（SAN、serverAuth、有效期 397 天，自动续期） |
| 访问控制 | 每次开始推流生成新的 8 位访问码（40 位随机）；扫码链接为一次性 144 位令牌；同一 IP 连续输错 5 次锁定 30 秒并指数递增；全网累计 20 次错误自动更换访问码；会话令牌 256 位、只存哈希、绑定观看者 IP、HttpOnly + Secure + SameSite=Strict |
| 网络范围 | 只接受来自 Wi‑Fi / 热点 / USB 共享等**局域网私有地址**的连接，在 TLS 握手前就拒绝移动数据、VPN、本机回环（其他 App）的连接；不做端口映射、不广播、不经云端 |
| 网页防护 | 严格 CSP（无内联脚本、无第三方资源）、禁止被嵌入、校验 Host（防 DNS 重绑定）和 Origin（防 CSRF / 跨站 WebSocket） |
| 隐私 | 只申请相机权限（**不申请麦克风**、存储、位置）；不录像、不保存；不含广告、统计、崩溃上报等任何第三方 SDK；App 从不主动联网 |
| 手机端 | 禁止截屏/录屏本应用；禁止系统备份和换机迁移；发布版不输出任何日志；不会开机自启，服务被系统杀死后不会自动重启 |
| 资源限制 | 最多 4 个观看者、32 个连接（单个设备最多 12 个），请求头必须在 10 秒内收完；严格的 HTTP 解析（长度限制、拒绝分块/重复头）；慢速观看者自动丢帧回到关键帧，不会拖慢别人 |

## 与现有方案的对比和取舍

调研了常见的开源/闭源方案后做的取舍：

- **DroidCam、Iriun、Camo、EpocCam 等**：观看端需要安装电脑客户端或虚拟摄像头驱动，且闭源。本应用只需要浏览器，任何设备都能看。
- **IP Webcam 一类的“手机变网络摄像头”应用**：思路相同（手机上跑网页服务），但常见做法是明文 HTTP/RTSP、可选密码，任何同网段的人都可能偷看或嗅探。本应用强制 TLS 1.3 + 一次性访问码 + 只限局域网。
- **云端监控类应用（需要注册账号）**：画面经过第三方服务器。本应用完全不经云端。
- **scrcpy 的摄像头镜像**：需要 Android 12 及以上和 adb，你的手机是 Android 11，用不了。
- **Android 14 自带的“USB 网络摄像头”**：需要 Android 14，同样不适用。
- **传输格式**：首选 H.264 硬件编码 + WebSocket + 浏览器 WebCodecs 解码（比 MJPEG 省 5~10 倍流量、更省电、手机不发烫）；没有 WebCodecs 的老浏览器自动回退到 MJPEG。没有采用 WebRTC，是为了避免引入十几 MB 的原生库和 ICE/STUN 带来的额外攻击面。
- **画面方向**：后置摄像头画面本身就不是镜像的；应用只对画面做旋转（数学上不可能产生镜像），网页端也只做缩放，不做任何翻转。

## 构建与发版（GitHub Actions）

发版流程：**签名 → 出安装包 → 生成 Release 草稿 → 本地测试通过 → 正式发布**。GitHub Actions 只负责构建、签名和发版，不在 Actions 里跑测试。

1. `main` 分支上有会进入 APK 的改动（`app/src/main`、`core/src/main`、Gradle 配置、`VERSION`、工作流本身）时，自动运行 [`release.yml`](.github/workflows/release.yml)：构建 release APK → 用仓库 Secrets 里的密钥签名 → 校验签名证书指纹和版本号 → 创建 **Release 草稿**（附 APK 和 `SHA256SUMS.txt`，草稿不公开，旧的未发布草稿会被删除）。只改测试或文档不会触发；也可以在 Actions 页面手动运行。
2. 在开发环境（Claude 的云端开发环境，不是用户的电脑或手机）中对同一个提交执行全部测试，其中包括 **Android 11 模拟器端到端测试**（见下方“测试”）。
3. 测试全部通过后，由开发环境运行 [`publish-release.yml`](.github/workflows/publish-release.yml)（“Publish tested release”，输入版本号，如 `v1.0.2`）：它会重新下载草稿里的 APK，核对 SHA‑256 和签名证书指纹，然后把草稿转为正式 Release（此时才创建 tag、对外可见）。测试不通过的草稿不会发布，修复后的新草稿会替换它。

- 版本号：`VERSION` 文件里的主次版本 + versionCode，例如 `1.0.37`。versionCode 取 `main` 分支的提交数，但绝不会小于已发布的最大值（即使改写过历史），保证每次更新都能覆盖安装；同一个提交不会重复发版。要升级主次版本，修改 `VERSION` 即可。
- **不占用 Actions 存储额度**：不使用 Actions 缓存、不上传构建产物（artifact），APK 只发布到 Releases（Release 附件不计入 Actions 存储额度）。仓库是公开的，GitHub 托管运行器的分钟数也不收费。
- 需要的仓库 Secrets：`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`（PKCS12，别名 `androidwebcam`）。密钥只保存在 GitHub Secrets 中，请勿提交到仓库（`.gitignore` 已屏蔽常见密钥文件）。
- 依赖尽量少：AndroidX/Compose（Google）+ ZXing core（本地生成二维码）；HTTP/TLS/WebSocket 服务器是自己实现的，没有引入第三方网络库。Gradle Wrapper 和 Actions 均做了校验/固定版本。

本地构建：

```bash
./gradlew :core:test :app:assembleDebug
```

## 测试（在开发环境中执行，通过后才正式发布）

一条命令完成全部检查（没有 KVM 的机器加 `EMULATOR_ACCEL=off`），最后输出 `ALL CHECKS PASSED` 才会发布：

```bash
tools/verify-release.sh
```

- 单元测试 + Android Lint：证书与 TLS 1.3 握手（含拒绝 TLS 1.2）、HTTP 解析的各种畸形请求、慢速请求和单设备连接上限、WebSocket、登录锁定/一次性二维码/会话、H.264 码流处理、旋转不会镜像、编码器尺寸回退等；Lint 同时检查 core 模块的 API 兼容性。
- 浏览器端到端测试（`tools/run-browser-tests.sh`）：用测试视频验证网页登录、H.264/MJPEG 播放、WebSocket 不通时自动切换 MJPEG、一次性二维码、CSP 无违规。
- **Android 11（API 30）模拟器测试**（`tools/run-device-tests.sh`）：
  1. 功能端到端：真实启动前台服务、相机、GPU 旋转、H.264 编码和 TLS 服务，通过模拟器的局域网地址登录、拉取 H.264 关键帧（并用 Android 解码器解码）和 MJPEG 画面，确认 TLS 私钥在 Android Keystore 中、画面为竖屏、回环连接被拒绝；
  2. **覆盖升级安装**：旧版本运行后用 `adb install -r` 安装新版本，确认是原地升级（不是重装）、设置保留、HTTPS 证书指纹不变（升级后浏览器不会再次提示证书）、推流正常；
  3. **正式版覆盖升级**：用上一个正式发布版本的代码构建旧 APK，新版本覆盖安装成功并能正常启动，且旧版本无法降级覆盖新版本。

### 真机测试清单（以 OnePlus Nord N10 5G / Android 11 为准）

1. 安装 Release 中的 APK，打开后点“开始推流”，允许相机权限，预览正常。
2. 电脑浏览器打开显示的地址，核对证书指纹后继续，输入访问码，能看到画面；状态栏显示约 720p、30 fps。
3. **镜像检查**：把一本书或写字的纸对着后置摄像头，网页上的文字应能正常阅读（不是反的）；人举右手，画面中右手在画面左侧（和拍照一致）。
4. 把手机横过来放稳约 1 秒，网页画面自动变为横屏且方向正确。
5. 按电源键熄屏 5 分钟，网页画面持续；通知栏显示观看人数。
6. 用另一台手机扫描二维码直接进入；再扫一次同一个二维码应提示已失效。
7. 输错访问码 5 次，应提示锁定；手机收到安全提醒。
8. 关闭手机 Wi‑Fi 只用移动数据时，地址列表为空，外部无法连接。
9. 从 Release 下载新版本直接安装，能覆盖升级。
